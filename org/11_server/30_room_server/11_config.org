* 配置文件
  #+begin_example
  配置文件(FkConfig, GoldConfig)
  |-- 房间规则的配置RoomRuleConfig :: 用来生成房间规则RoomRule
  |
  |-- 场次(房卡场, 金币场, 比赛场)的房间配置 :: 用来生成FkRoomConfig, GoldRoomConfig
  |   例如: 金币场的等级, 允许进入的最小, 最大金币
  #+end_example

  #+attr_shortcode: info
  #+begin_hint
  下发给client 的数据:
  - 房卡场: ClientFkConfig. ClientFkConfig 是FkConfig中需要下发的部分
  - 金币场: GoldRoomConfig. 直接下发金币场配置信息即可
  #+end_hint


* 设计思路
  1. 为了减少人为失误, 程序应该保证配置文件与 {RoomRule, FkRoomConfig/GoldRoomConfig} 完全匹配.
  2. 每个场次都有自己的配置文件. 例如:
     fk.config, gold.level1.config, gold.level2.config


* 代码实现思路
  1. 为了实现设计原则1, 需要比对 {=RoomRule=, =FkRoomConfig/GoldRoomConfig}= 和 =配置文件=
     #+begin_src protobuf
       message RoomRule {
         RoomRuleCommon common           = 1;  // 通用房间规则
         bytes subgame                   = 2;  // 子游戏规则. 对应子游戏的SubRoomRule
       }
     #+end_src

     其中, =RoomRule.subgame= 实际存储的是子游戏的 =SubRoomRule=

  2. 配置文件统一采用 TOML 格式

  3. 为了方便比对 ={=RoomRule=, =FkRoomConfig/GoldRoomConfig}= 与 =toml配置=
     约定 ={=RoomRule=, =FkRoomConfig/GoldRoomConfig}= 只的每个 ~field~ 对应 TOML 中的一个 ~table~


* 代码实现v0.1

  #+begin_example
  Class FkConfigLoader    读取并保存 fk   场次的配置
  Class GoldConfigLoader  读取并保存 gold 场次的配置

  Class RoomRuleBuilder   根据配置构造房间规则
  #+end_example


  Loader流程:
  1. 读取配置
     读取配置文件, 并将配置内容解析后保存到 =toml_tables= 中, 定义如下:
     #+begin_src C++
       std::map<std::string, T> toml_tables
     #+end_src

     其中, key 为 TOML table 的 path, T 为对应配置 table 的数据类型,
     具体类型根据场次的配置定义.

  2. 校验配置
     1) 首先比对 =toml_tables.key= 与 =fileds=, 确保完全匹配
     2) 其次校验配置内容是否符合对应到业务规则.

  3. 构造场次配置
     根据配置内容构造该场次特有的配置信息


* 代码实现v0.2
  v0.2 主要进行一下调整:

  1. 通过梳理 v0.1 的流程, 发现配置文件都需要与 =proto::RoomRule= 进行匹配校验,
     因此, 可以将 =proto::RoomRule= 中的 fields 提前读取并保存.

  2. 同时增加 =ConfigManager= 作为配置模块的对外接口, 屏蔽不同场次配置的具体实现.

  #+begin_example
    Config 模块

    Class ConfigManager          配置模块对外接口
    |
    |-- Class FkConfigLoader     读取并保存 FK 场次的配置
    |
    |-- Class GoldConfigLoader   读取并保存 Gold 场次的配置
    |
    |-- Class RoomRuleBuilder    根据配置构造房间规则
    |
    |__ Class RuleSchemaLoader   读取proto::RoomRule 中所有的fields
  #+end_example


  #+attr_shortcode: info
  #+begin_hint
  上面的 Class 仅表示一个独立的功能模块, 并不特指 C++ 中的 =class= 类型.
  具体实现可以是 =class=, =namespace=, 也可以是其他形式的代码组织单元
  #+end_hint
