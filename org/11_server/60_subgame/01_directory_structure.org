#+title: 目录结构

* 目录结构
  子游戏统一存放在项目目录下的src/subgames目录中,
  每个子游戏使用对应的 kindid 作为目录名称, 实现子游戏之间的目录隔离

  #+begin_example
  |-- cmake                   //
  |-- proto                   //
  |-- proto_code_generator    //
  |-- scripts                 //
  |-- src                     //
  |   |-- client              //
  |   |-- common              //
  |   |-- db                  //
  |   |-- gate                //
  |   |-- room                //
  |   |-- subgame             // 子游戏存放位置
  |   |   |-- 1               //
  |   |   |-- 11              //
  |   |   |-- 22              //
  |   |   `-- CMakeLists.txt  //
  |   `-- CMakeLists.txt      //
  |-- tests                   //
  |-- CMakeLists.txt          //
  `-- readme.org              //
  #+end_example



  每个子游戏独立管理自身的conf配置文件、Protocol Buffer 定义及cc文件
  子游戏之间保持目录隔离，避免资源和业务逻辑相互耦合

  #+begin_example
    |-- auto_generated           // 自动生成的代码
    |   `-- table_sink.h         // 子游戏桌子
    |-- conf                     //
    |-- proto                    //
    |   |-- constant.proto       // 与client约定的常量定义
    |   |-- msg.proto            // 消息协议
    |   `-- sub_room_rule.proto  // 子游戏房间规则
    |-- constant.h               // server自己使用的常量定义
    |-- data.h                   // 数据模型
    |-- data.cc                  //
    |-- flow.h                   // 流程模型
    |-- flow.cc                  //
    |-- sub_handler.cc           // Message Handler的定义
    `-- table_sink.cc            //
  #+end_example
