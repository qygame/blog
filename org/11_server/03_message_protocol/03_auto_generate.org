#+title: 自动生成


* 自动生成
  Proto 文件本质是Service 接口的定义.
  Service 接口分为Client Message 和 Other Service API, 因为Proto 文件也与之一一对应.
  以Gate Service 为例:

  | Service 接口      | Proto文件          |
  |-------------------+--------------------|
  | Client Message    | gate.proto         |
  | Other Service API | gate_service.proto |

-----

* Client Message
  自动生成目标:
  | 文件             | 作用                 | 使用对象 |
  |------------------+----------------------+----------|
  | client_handler.h | Sub 接口的声明       | Service  |
  | cmd_sender.h     | Cmd 接口的声明和定义 | Service  |


  文件的作用:
  1. handler
     1) 避免手动维护 { 消息协议, 处理函数 }
     2) 解析目标Message
  2. sender
     1) 避免手动维护 { main_command, sub_command, proto message }, 简化调用流程

  #+attr_shortcode: info
  #+begin_hint
  因为已经有sender 了, 代码中不应该再出现kernel::Send函数
  #+end_hint
  -----

* API
  自动生成目标:
  |                    |                                            |          |
  | 文件               | 作用                                       | 使用对象 |
  |--------------------+--------------------------------------------+----------|
  | api_local.h        | 本地API 接口声明                           | Service  |
  | api_remote.h       | 远程API 接口声明                           | Service  |
  | api_remote.cc      | 远程API 接口定义                           | Service  |
  | service_handler.cc | 绑定本地API 对外接口与ApiLocal             | Service  |
  |                    | 绑定Client Message 对外接口与ClientHandler | Service  |
  | endpoint.h         | Service 对外调用入口                       | Caller   |
  | endpoint_local.h   | LocalEndpoint 的声明和定义                 | Caller   |
  | endpoint_remote.h  | RemoteEndpoint 的声明和定义                | Caller   |


  1. api_local, api_remote 避免手动维护 { 消息协议, 处理函数 }
  2. service_handler 避免手动维护 {Service 接口入口, 接口具体实现 }
  3. endpoint 解耦 Caller 与 Service. 同时静态检查接口是否存在(仅限APIi)

-----

* 设计说明
  #+attr_shortcode: info
  #+begin_hint
  为了接口定义与处理函数一一对应 (删除过时的处理函数, 找到未处理的协议)
  处理函数的声明放在了class 中, 在编译链接期就发现问题, 而不是等到运行时候.
  #+end_hint
