* 自动生成
  如果是消息协议proto文件, 会自动生成:
  1. sub 协议的 handler
  2. cmd 协议的 handler
  3. cmd 协议的 sender


  如果是Service proto文件, 会自动生成:
  1. Service Server
  2. Service Client

  -----
* 消息协议
  以login.proto 为例:

  |             | 文件                | 作用                          | 所在对象    |
  |-------------+---------------------+-------------------------------+-------------|
  | sub handler | login.sub_handler.h | 生成Sub协议对应的处理函数声明 | LoginServer |
  | cmd handler | login.cmd_handler.h | 生成Cmd协议对应的处理函数声明 | TestClient  |
  | cmd sender  | login.sub_sender.h  | 生成Cmd协议对应的发送函数     | LoginServer |

  1. sub handler 在 LoginServer 中使用并实现其中函数定义.
     sub handler 存在的意义:
     1) 避免手动维护 { 消息协议, 处理函数 }
     2) 提前解析 kernel::Message -> SubMessage
  2. cmd handler 在 TestClient  中使用并实现处理函数定义
     cmd handler 只对TestClient 有意义:
     1) 避免手动维护 { 消息协议, 处理函数 }
     2) 提前解析 kernel::Message -> SubMessage
  3. cmd sender 在 LoginServer 中使用. 存在的意义:
     1) 避免手动维护 { main_command, sub_command, proto message }

  #+attr_shortcode: info
  #+begin_hint
  TestClient 是服务器模拟的client, 用来模拟玩家发送消息.
  主要用来测试Server 的稳定性
  #+end_hint

  -----

* Service
  以task_service.proto 为例:

  |                | 文件                 | 作用                      | 调用对象   |
  |----------------+----------------------+---------------------------+------------|
  | Service Server | task_service.h       | 生成Service的函数声明     | TaskServer |
  | Service Client | task_service_stub.h  | 封装对 TaskService 的调用 | 其他Server |
  |                | task_service_stub.cc |                           |            |


  1. Service Server 意义:
     1) 避免手动维护 { Service 协议, 处理函数 }
  2. Service Client 意义:
     1) 简化对TaskService 的调用


  task_service_stub 示例:
  #+begin_src C++
    // task_service_stub.h
    namespace qy::task_server {
    void PushTask(const kernel::SessionPtr, const proto::SubPushTask&);

    } // namespace qy::task_server


    // 其他server 中, 调用
    proto::SubPushTask sub;
    task_server::PushTask(session, sub);
  #+end_src

-----
* 设计说明
  #+attr_shortcode: info
  #+begin_hint
  为了协议(消息协议或Service协议)与处理函数一一对应 (删除过时的处理函数, 找到未处理的协议)
  所有的handler 都放在了class 中
  #+end_hint
