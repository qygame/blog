* 服务器架构: 登录流程
  #+begin_src mermaid :file result.png
    sequenceDiagram
        participant Client
        participant LB as LB集群
        participant LoginServer
        participant GateServer
        participant ActorServer
        participant Reids

        Client->>LB: 账号、密码
        LB->>LoginServer: 转发
        LoginServer->>LoginServer: 查询数据库,校验登陆权限
        LoginServer->>Redis: 获取GateServer列表及负载
        Redis-->>LoginServer: 返回GateServer列表
        LoginServer->>LoginServer: 选择GateServer, 生成Token
        LoginServer->>Redis: 保存Token与登陆上下文
        LoginServer-->>LB: 返回GateServer Ip、Port以及Token
        LB-->>Client: 转发

        Client->>GateServer: Token
        GateServer->>Reids: 校验Token
        Reids-->>GateServer: 返回Token对应的上下文
        GateServer->>GateServer: 记录map(uid, session)
        GateServer->>ActorServer:  角色登陆(uid)
        ActorServer->>ActorServer: 创建User
        ActorServer-->>GateServer: 返回用户数据
        GateServer-->>Client: 转发
  #+end_src

  1. Client -> LB集群: DNS 或者 Anycast
  2. LB集群 -> LoginServer: LB通过轮询在LoginServer 集群中选择LoginServer
  3. LoginServer 返回GateServer信息: GateServer集群定期向redis上报自身数据. LoginServer根据策略在集群中选择合适的GateServer
  4. GateServer -> ActorServer: GateServer根据uid 通过一致性Hash 选择ActorServer

* 设计说明
  1. 分层、集群的设计, 只是对资源的妥协
     如果计算资源是无限的, 就不需要再去使用分层、集群

  2. 对于服务器, 最重要的不是分层、集群, 而是灾后重建
     从错误或崩溃中恢复 才是需要重点考虑的
