* 服务器架构: 登录流程
  #+begin_src mermaid :file result.png
    sequenceDiagram
        participant Client
        participant LB as LB集群
        participant LoginServer
        participant GateServer
        participant ActorServer

        Client->>LB: 账号、密码
        LB->>LoginServer: 转发
        LoginServer-->>LB: 在redis生成Token, 返回GateServer信息,Token
        LB-->>Client: 转发

        Client->>GateServer: Token
        GateServer->>ActorServer: 校验Token, 然后通知用户登陆
        ActorServer-->>GateServer: 下发用户数据
        GateServer-->>Client: 转发
  #+end_src

  1. Client -> LB集群: DNS/Anycast 将域名解析分发给不同的LB (Nginx/Cloud NLB)
  2. LB集群 -> LoginServer: LB通过轮询在LoginServer 集群中选择LoginServer
  3. LoginServer 返回GateServer信息: GateServer集群会定时往中redis中写入数据. LoginServer根据策略在集群中选择GateServer
  4. GateServer -> ActorServer: GateServer根据uid 通过一致性Hash 选择ActorServer

* 设计说明
  1. 分层、集群的设计, 只是对资源的妥协
     如果计算资源是无限的, 就不需要再去使用分层、集群

  2. 对于服务器, 最重要的不是分层、集群, 而是灾后重建
     从错误或崩溃中恢复 才是需要重点考虑的
