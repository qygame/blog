    玩家退出模块

    • 玩家申请退出房间
    • 玩家确认解散申请
    • 能否直接离开
    • 能否解散

    玩家退出模块 SubPlayerExit 负责玩家退出Table 的流程, 包括:

    1. 直接退出
    2. 解散表决退出

    退出方式由 Server 根据当前桌子状态及玩家状态决定, Client 不需要区分退出方式, 只提供统一的「退出房间」入口

    玩家退出模块 SubPlayerExit 与 PlayerAction.Leave 不一样.
    PlayerAction.Leave 强调的是玩家Leave 这个动作;
    SubPlayerExit 强调的是退出流程

    玩家申请退出房间#

    flowchart TD
    玩家申请退出房间 --> if1{能否直接离开}

    if1 -->|yes| 玩家离开房间
    if1 -->|no| if2{能否申请解散}

    if2 -->|yes| 通知玩家需要解散表决才能退出
    if2 -->|no| 通知玩家退出失败

    玩家确认解散申请#

    玩家收到「需要解散表决才能退出」提示后, 可以选择确认或取消
    由于玩家可能不会立即确认, 在此期间, 桌子状态, 玩家状态等数据可能发生了变化.
    因此, 玩家确认申请解散时, Server 必须重新判断当前状态

    flowchart TD
    玩家确认解散申请 --> if1{能否直接离开}

    if1 -->|yes| 玩家离开房间
    if1 -->|no| if2{能否解散}

    if2 -->|yes| 广播解散投票 --> if3{投票通过}
    if2 -->|no| 通知玩家退出失败

    if3 -->|yes| 解散房间
    if3 -->|no| 房间继续运行

    能否直接离开#

    根据桌子状态, 玩家状态来判断是否允许直接离开

    如果桌子处于空闲和小局结束状态, 允许直接离开
    如果玩家未处于游戏状态, 允许直接离开

    能否解散#

    只有房卡场才允许解散房间
