    服务器架构#

    architecture-beta
%% client
service client(internet)[Client]

%% Server
group servers(server)[Servers]
service gate(server)[Gate] in servers
service room(server)[Room] in servers
gate:R <-- L:room

%% 数据层
group dbs(database)[Databses]
service redis(database)[Redis] in dbs
service postgres(database)[Postgres] in dbs
redis:R -- L:postgres

%% 指向
client:R --> L:gate

gate:B --> T:redis{group}

    服务器说明#

    [ 客户端 Client ]
       │
       │ 1. DNS / Anycast 将域名解析分发给不同的 LB IP
       ▼
[ LB 集群 (Nginx / Cloud NLB) ] ── (第一层负载：入口分流、解密 HTTPS)
       │
       │ 2. LB 通过 HTTP 轮询转发给不同的 LoginServer
       ▼
[ LoginServer 集群 ]            ── (第二层负载：无状态鉴权、业务逻辑计算)
       │
       │ 3. Login 查 Redis 挑选最空闲的 Gate，把 Gate IP 返回给 Client
       ▼
[ GateServer 集群 ]             ── (第三层负载：重定向直连，平摊海量长连接)
       │
       │ 4. Gate 根据 RoleID 通过一致性 Hash 路由给指定的 Actor
       ▼
[ ActorServer 集群 ]           ── (第四层负载：有状态计算，按 RoleID 动态加载)

    帐号登陆:
    loginServer根据 帐号, 密码 与数据库比对. 成功的话:

    1. 获取gate server 的ip, port (从redis中查询获取, loginServer与GateServer分离)
    2. 在redis中写入roleID ->token.
    3. 返回gate server, token给client
    4. client 去连接gateServer, 并携带token
    5. gateServer比对redis中的roleID, token 是否一致.
      如果一致, 则通知ActorServer (这里使用强hash计算出ActorServer)
    6. ActorServer中处理重复登陆
      通知old GateServer 踢人; 记录新的GateServer

    帐号注册:

    1. 写入数据库
    2. 写入成功, 复用帐号登陆逻辑

    断线重连的逻辑:

    1. 断线之后, client首先连接GateServer
      GateServer保存一段时间ttl, 如果在此期间正常连接. 无事发生
      ttl之后, GateServer删除连接信息, 并通知到ActorServer
      Client 需要重新连接loginServer分配GateServer
